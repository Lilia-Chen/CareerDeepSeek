# P2.1 Chrome App Profile — Design Spec

**Status:** Current architecture spec
**Date:** 2026-06-20
**Scope:** Full Chrome App Profile implementation for managed Chrome region tagging and filtering

---

## Positioning

P2.1 is not direct AUV command-surface alignment. It is a CDS managed-Chrome reliability layer that builds on P2's AUV-shaped atomic commands.

AUV regular UI commands operate against a resolved app/window target and do not model Chrome-specific UI regions. CDS needs this layer because its target is a managed Chrome profile with browser chrome, page viewport, AX evidence, OCR evidence, and safety gates all mixed in one captured window.

This feature must be implemented in full. Do not ship a partial region enum, fixed-pixel heuristic, or docs-only profile. The output of this feature is a usable app-profile model that every relevant observation, recognition, and action command can consume consistently.

---

## Goals

1. Tag observed Chrome evidence with semantic regions.
2. Keep browser chrome evidence visible instead of deleting it.
3. Let recognition/action commands opt into region filtering.
4. Replace hardcoded browser-chrome pixel thresholds with a Chrome App Profile model.
5. Preserve managed profile safety: commands still act only inside the leased managed Chrome window.

---

## Current Baseline

Already present:

- `profile.json` loaded by `loadProfileConfig()`.
- managed Chrome bootstrap and lease validation in `MacOSChromeDriver`.
- `chrome.checkSafetyGate`.
- `--target managed` CLI support.
- full-window capture, OCR, OCR row grouping, AX capture, and atomic commands.
- trace evidence for screenshots, capture contracts, OCR reports, AX reports, and action results.

Missing:

- semantic region tags on observed nodes.
- a shared Chrome app profile model.
- region-aware matching for OCR, OCR rows, AX text inputs, and AX buttons.
- command output that explains when a match came from browser chrome versus page viewport.

## Region Model

Define a semantic region type:

```ts
export type ChromeAppRegion
  = | 'chrome_menu_bar'
    | 'chrome_tab_strip'
    | 'chrome_toolbar'
    | 'chrome_address_bar'
    | 'chrome_bookmarks_bar'
    | 'page_viewport'
    | 'browser_chrome'
    | 'unknown'
```

Rules:

- `page_viewport` is the page content area where normal website actions should default.
- `browser_chrome` is a coarse fallback for Chrome-owned UI when a more specific region cannot be proven.
- `unknown` means the profile could not classify the evidence safely.
- Region tags are metadata. They must not delete evidence.

## Chrome App Profile Module

Create `src/computer-use/macos-chrome-driver/chrome-app-profile.ts`.

Responsibilities:

- derive Chrome structural landmarks from AX evidence when available.
- classify AX node bounds into `ChromeAppRegion`.
- classify OCR match and OCR row bounds into `ChromeAppRegion` using the same resolved profile geometry.
- expose known limits when profile geometry is incomplete.
- avoid fixed global pixel constants such as "top 96 px is browser chrome" as verified profile facts.

Required public functions:

```ts
export interface ChromeAppProfile {
  windowBounds: { x: number, y: number, width: number, height: number }
  pageViewportBounds?: { x: number, y: number, width: number, height: number }
  regions: Array<{
    region: ChromeAppRegion
    bounds: { x: number, y: number, width: number, height: number }
    confidence: 'verified' | 'inferred'
    source: 'ax' | 'fallback'
  }>
  knownLimits: string[]
}

export function buildChromeAppProfile(input: {
  windowBounds: { x: number, y: number, width: number, height: number }
  axRoot?: AXNode
}): ChromeAppProfile

export function classifyChromeRegion(input: {
  profile: ChromeAppProfile
  box: { x: number, y: number, width: number, height: number }
}): ChromeAppRegion
```

Fallback behavior:

- If AX structural evidence cannot identify a page viewport, classify safely as `unknown` or `browser_chrome`.
- Conservative fallback regions are allowed only when they are explicitly marked `confidence: 'inferred'`, `source: 'fallback'`, and accompanied by known limits.
- Do not silently claim `page_viewport` from a hardcoded top inset or expose fallback geometry as a verified AX-derived profile.

## Observation Integration

`chrome.observe` must include region tags on relevant evidence nodes:

- AX nodes.
- OCR text nodes.
- OCR row evidence when rows are surfaced.
- action-relevant merged nodes.

Each tagged item must expose:

```json
{
  "region": "page_viewport",
  "region_confidence": "verified",
  "region_source": "ax"
}
```

If classification is incomplete:

- keep the node.
- set `region: "unknown"` or `region: "browser_chrome"`.
- include `known_limits`.

## Command Filtering

Add optional semantic region filters to recognition/action commands:

```bash
cds invoke chrome.findText --query "LangChain" --region page_viewport
cds invoke chrome.clickText --query "LangChain" --region page_viewport
cds invoke chrome.findRows --region page_viewport
cds invoke chrome.clickRow --row_index 1 --region page_viewport
cds invoke chrome.focusText --query "Search" --region page_viewport
cds invoke chrome.pressButton --query "Submit" --region page_viewport
```

Rules:

- `--region` accepts only `ChromeAppRegion` values.
- Default behavior is command-specific:
  - OCR text/row commands default to all regions for backward compatibility unless the command explicitly opts into `page_viewport`.
  - page actions may recommend `page_viewport` in docs but must not silently hide browser chrome evidence.
- If a region filter removes all matches, return completed no-match output with `matchCount: 0`.
- Output must include the region on every returned match.
- Do not use region filtering to bypass safety gates.

---

## Safety Rules

Region filtering is not permission. The existing managed Chrome safety model remains mandatory:

- profile lease must match the managed profile.
- actions must target the resolved managed Chrome window.
- hard-stop detection still refuses dangerous states.
- clicks outside the managed window remain invalid even if a region label exists.

Browser chrome actions are allowed only when explicitly requested by region or by a command whose purpose is browser chrome interaction. P2.1 does not add browser navigation commands.

---

## Trace and QA

Trace artifacts must record region metadata:

- capture/observation artifacts include profile known limits.
- OCR and AX reports include match regions.
- action result artifacts include selected region and region source.
- QA reports aggregate region-related known limits.

Visual trace reports should render region labels when present, but P2.1 does not require a new inspect server.

---

## Tests

Required coverage:

- profile builder classifies AX-derived page viewport.
- profile builder emits known limits when AX structure is incomplete.
- OCR match classification uses the capture contract and profile geometry consistently.
- AX match classification uses global logical bounds directly.
- `--region page_viewport` filters OCR text matches.
- `--region page_viewport` filters AX text-input/button matches.
- filtered no-match returns completed no-match output, not failure.
- browser chrome evidence is retained in observe output with a browser region tag.
- no production source uses hardcoded browser-chrome top inset constants.

---

## Non-Goals

- No general app-profile framework beyond Chrome.
- No fixed company-search workflow.
- No browser back/close/reload commands.
- No tab switching commands.
- No hidden deletion of browser chrome evidence.
- No replacement for profile safety gates.
- No AUV compatibility claim; this is a CDS managed-Chrome enhancement.
